## 一、⭐⭐ 判定口径（**审查者给的那句 ✗ 我采纳** ✓）

> 「**读集 ✗ 写入目标 ✗ 被验证对象 ✗ 执行身份 —— 这四样决定一个结论能不能成立。**」

⇒ ⭐ **我把它固化成四条必查项**：
```
① **读集**：声称的依据真的被读到了吗？
② **写入目标**：两支的写入目标（含运行资源）真的不重叠吗？
③ **被验证对象**：这个结论是**哪一份**（哪个版本）上的？
④ **执行身份**：这次活动是**谁**在**什么时候**做的？
```

## 二、⭐⭐ 修订后的规则（**11 条 ✗ 前 10 条来自审查者 ✗ 第 11 条是我从 L11 这次加的** ✓）

```
1. **结论只对"被验证的那个对象"成立** ✗ 不迁移到改版 ✗ 整合版或另一个候选 ✓
2. ⭐ **未读取即未验证**；读集为空而声明验证通过 ✗ **等于没有验证** ✓
3. ⭐ **写入冲突不限于业务文件 —— 共享输出路径就是冲突** ✗ 后写覆盖先写 ✓
4. ⭐ **输入相同（同 SHA-256）不等于检查集相同** ✗ 更不等于结论可以互相替代 ✓
5. ⭐ **同一输入上的失败项是信号不是噪声** ✗ 不能被通过项盖掉 ✓
6. ⭐⭐ **角色名 ✗ 栏位名是标签 ✗ 不是执行证据；证据是**身份 + 时间窗口 + 事件记录**** ✓
7. ⭐ **"并行"需要可核实的独立执行痕迹** ✗ 否则只能说**顺序** ✓
8. **部分覆盖不能表述为整体通过** ✓
9. ⭐ **检查器给"允许"只表示未拦截** ✗ 不表示任务被完成 ✓
10. ⭐ **每条审查结论都要标出：哪些是案例事实支持的 ✗ 哪些还需要核对什么** ✓
11. ⭐⭐ **【我加的】声明里的路径 ✗ 命令 ✗ 版本号 ✗ 必须**自己核一遍能不能对上**** ✓
    ⇒ **`agent/schedule.py` 只比对**声明的路径**✗ 它不检查**
      · **路径在候选里存不存在**
      · **版本号是怎么算出来的**
      · **命令在当前目录能不能跑**
    ⇒ ⭐ **我这次三处都踩了**：
      · 给甲的读集里写了 `docs/courses/L11/实践操作手册.md` ✗ **候选里没有那个目录** ✓
      · 给两边的 `input_version` 用的是**我自己拼的合并哈希 ✗ 算法没写进合同** ⇒
        **甲核对不了** ✓
      · 第一版 `while read` 跑模式清单**漏了最后一行**（**文件末尾无换行** ✓）
    ⇒ ✅ **所以"声明通过检查"与"声明可用"是两件事** ✗ **必须自己核** ✓
```

## 三、⭐ 每次委派前要写的四样（**模板** ✓）

```
① **读集**：逐条列出 ✗ **并确认每一条真的存在于那个工作目录** ✓
② **写集**：逐条列出 ✗ **只读的用空写集表达 ✗ 不靠提示词** ✓
③ **运行资源**：各自的临时目录 ✗ 数据库 ✗ 报告路径 ✗ 端口 ✓
④ **输入版本**：⭐ **给出**可独立复算**的算法 ✗ 不是只有我知道的一个数** ✓
   ⇒ ✅ **正确做法**（**甲示范的** ✓）：**逐文件哈希** ✗ 各自列出来 ✗ 让对方自己算 ✓
```

## 四、⭐⭐ 收到结果后要做的五步（**模板** ✓）

```
① **复现**：自己跑同一条命令 ✗ 对数字（**退出码 ✗ 用例数 ✗ 失败数 ✗ 文件哈希** ✓）
② **分类**：**已证实 / 待验证 / 需求未定** ✗ **逐条标出处** ✓
③ **核范围**：用**自己的快照**比 ✗ 不看对方声明的写集 ✓
④ **定性**：⭐ **先看 `git diff HEAD`** ✗ **"工作树 == 起始标签"是一个假设 ✗ 不是事实** ✓
⑤ **保留失败**：**旧版本的失败不被新版本的通过盖掉** ✗ **分开陈述适用范围** ✓
```
