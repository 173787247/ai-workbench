# FDE_SPEC 模板（六段合同）

> ⭐ **本模板只抽取六节标题和提问方式 ✗ 不含任何一次需求的业务答案。**
> 用法：复制本文件为 `lesson-0N-submission/FDE_SPEC.md` ✗ 逐节把「填写提示」换成**你确认过的内容**。
> ⚠️ **没有来源的项写「待确认」✗ 不要抄别的需求的答案** ✗
> **不要在拿到具名确认前把文件称为"确认版"。**

## 来源

**这里应填写什么**：这次需求**从哪里来** —— 提出人的原话（**照抄 ✗ 不要转述成术语**）、
**使用目的**（**使用者拿结果做什么决定**）、**确认人**、**本次练习或交付的身份**。
⚠️ 若现有手段已能满足目的，先记下**为什么仍然要做**。**没有来源的项写「待确认」。**

## 目标

**这里应填写什么**：**一句话**说明这次要交付什么。
⚠️ **不要写"优化""提升"这类无法反驳的词**；要写到**可以用一个例子判断做到了没有**。

## 非目标

**这里应填写什么**：这次**明确不做**什么 —— 尤其是**容易被顺手做掉**的动作
（发通知 ✗ 自动改别的数据 ✗ 修改历史记录）。
⚠️ 每条都应该是**能观察的**（做完之后能看出它确实没发生）。

## 约束

**这里应填写什么**（**逐项 ✗ 缺哪项写「待确认」**）：

| 约束项 | 填写提示 |
|---|---|
| **列 / 字段与顺序** | 输出或接口的**确切**字段名与**排列顺序** |
| **计算口径** | 每个派生数字**怎么算出来的**（写出式子 ✗ 并给一个能验算的例子） |
| **数据粒度** | ⭐ **一行代表什么** —— **这是最容易被"为了简洁"合并掉的一项** |
| **排序** | 多行按什么键排 ✗ 是否**稳定**（两次运行结果可否逐字节比较） |
| **调用分工** | 谁调谁 —— 入口 ✗ 业务计算 ✗ 数据访问 ✗ 输出各在哪 |
| **允许修改范围** | **最小写集** —— 只允许改哪些文件 |
| **权限** | 在**哪一层**检查 ✗ 用**哪个**入口 |
| **错误处理** | 失败时**抛什么 ✗ 不做什么**（尤其：不许静默返回空） |

## 验收用例

**这里应填写什么**：**能被反驳**的检查项。**至少覆盖**：

| 类别 | 填写提示 |
|---|---|
| **正常路径** | 用一个**能算出来的例子**（数字要写进合同） |
| **空输入** | 没有任何数据时输出什么（表头？空文件？报错？） |
| **特殊字符** | 中文 ✗ 分隔符 ✗ 引号 ✗ 换行怎样保真 |
| **写出失败** | 旧文件与半成品怎样处理 ✗ 失败后什么必须不变 |
| **权限不足** | 被拒绝还是返回空 |
| **不变状态** | ⭐ 成功和失败时 ✗ 哪些数据一行都不能变（并说明怎样验证） |

## 完成定义

**这里应填写什么**：**交回什么**（文件 ✗ 版本 ✗ 内容指纹）、**检查到什么程度**、
**还缺哪些决定由谁作**。
⚠️ ⭐ **分别写清"结构 / 合同合格"与"业务结果合格" ✗ 两者各有自己的证据。**
⚠️ **没有具名接受决定之前 ✗ 状态保持 draft。**
